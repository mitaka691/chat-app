# chat-app
чат приложение с end-2-end криптиране

Представлява проста клиент-сървър чат система с end-to-end криптиране.

- RSA се използва за размяна на ключове
- AES-256-GCM се използва за криптиране на съобщенията
- Сървърът само препраща данни (не ги декриптира)

Структура на пакетите:

Всеки пакет има следната структура:

- [TYPE (1 byte)] + [DATA (variable)]

Типове пакети:
TYPE_PUBLIC_KEY (1) - съдържа RSA публичен ключ (PEM формат)
TYPE_AES_KEY (2) - съдържа AES ключ, криптиран с RSA
TYPE_MESSAGE (3) структура: [IV (12 bytes)] + [TAG (16 bytes)] + [CIPHERTEXT]

Криптография

RSA (2048-bit) - използва се за сигурна размяна на AES ключ
AES-256-GCM осигурява конфиденциалност, интегритет (чрез TAG)

Трудности:

1. Синхронизация между клиенти
Обикновено съобщенията се получават преди AES ключ, затова се добавя проверка "aes_ready".

2. Смесване на типове пакети
По същото време заедно с публичните ключове се бъркат и се добавя TYPE byte в началото

3. RSA декриптиране грешки
По време на декриптирането, може ключа да е грешен или самата логика да се обърка,
прави се строго "ръкостискане" (първо ключовете, после съобщенията)

4. Частично изпращане/получаване
При самия трансфер, обикновените send() и recv() не гарантират напълно прехвърлените данни, затова send_all() и recv_all() подсигуряват пълния трансфер на данни.
